# Mobile construction orders

Produced Arm Construction Vehicles, Construction Kbots and Minelayers now expose their original build menus. Select a completed builder, choose a structure, choose **Place selected structure**, then click within its build range. Right-click/S stops its construction; clicking an unfinished structure resumes work with the selected builder. A successful movement order interrupts construction and preserves the unfinished target. Each mobile builder has an independent job, so it can work alongside the Commander and factories.

The host waits for the builder to stop, invokes original StartBuilding with a target-relative heading, and waits for the script's construction-stance value 5 before applying work. StopBuilding closes the construction arm when work finishes or is cancelled. WorkerTime, BuildTime, costs and health use the shared construction primitive. The selected source controls menu eligibility, range, resource requests and script readiness; Commander control remains separate.

48 host checks cover the three builder types, original menu/range enforcement, waiting for the arm, partial work, pause/resume, concurrent Commander construction, completion, closing stance, faults, move-order cancellation and distant-resume rejection. The real-map viewer demo constructs a Vehicle Plant, produces a Construction Vehicle, moves/selects it, uses its menu to place a solar collector and completes that collector. A rendered capture was inspected. Run Godot with `--path godot -- --builder-demo --capture ABSOLUTE_PNG_PATH`. Both host and viewer cases are in the normal verification suite.

The earlier 3,661-snapshot native mobile-script comparison includes the builders' Activate/StartBuilding/StopBuilding/Deactivate paths with supplied angles. It validates interpreter execution, not the new world order scheduler. Current order timing, heading/pitch inputs, immediate resource payment and factory/mobile-builder/Commander spending order remain provisional. There is no automatic approach to distant construction sites, reclaim, repair, build queues for mobile builders, or native resource arbitration yet. Minelayers can construct their menu entries, but mine cloaking, triggering and damage still require combat systems.

Builder tests exposed two navigation integration issues. Odd-sized building cells now use the same integer grid anchor as odd-sized mover footprints. Also, when a turn would translate a unit into an obstacle, provisional movement retains its route and heading change while stopping translation, allowing it to turn clear rather than permanently dropping the route. The native steering primitive is unchanged. Neither change establishes faithful original placement or collision behavior; native yard/terrain comparisons and dynamic unit avoidance remain outstanding.

## Core mobile builders

Core Construction Vehicles, Construction Kbots and Minelayers use the same host path, with corcom as the Commander. Their menus show every original entry, but only natively verified Core types are placeable (`ConstructionWorld.supported`). Besides the resource buildings and ground factories, this now includes Core energy/metal storage (corestor, cormstor), Dragon's Teeth (cordrag) and all six Core mines (cormine1..6). `native_structure_reference.py` plays each script's healthy Create plus 600 idle ticks in the original interpreter with construction finishing at tick 30; `compare_native_structures.gd` matches all 5,409 snapshots (native-core-structure-validation.json). These scripts are simple: storage keeps one sleeping smoke thread, and mines and Dragon's Teeth only run Create. The comparison excludes damage smoke, SweetSpot/Killed, mine cloaking/triggering and combat. Defenses (corllt, corhlt, corrl, corpun, corvipe), radar, geothermal, advanced/air/naval factories and the construction pad (corhp) remain unverified and unplaceable.

The host builder test now covers all six builder types (102 checks), including rejection of an unverified Core entry, script-backed completed Core structures, and Core storage raising team capacity by the original EnergyStorage/MetalStorage values. Its partial-progress sample now stops once work is under way because cormine1 (BuildTime 665) finishes within the former fixed 250-tick window. `--core-builder-demo` boots Core, builds corvp, produces corcv and uses its menu to complete corsolar; the demo tries nearby sites in a fixed order because faction footprints differ. A rendered capture was inspected. Both demos run in the normal verifier; the structure oracle runs under `-Native`.

Full-game reconstruction remains active: Core coverage, weapons, projectiles, damage, opponents, missions and the remaining game systems are still required.

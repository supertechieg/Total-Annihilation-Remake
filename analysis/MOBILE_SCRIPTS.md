# Arm and Core factory product script playback

All twelve units in the original Arm Vehicle Plant and Kbot Lab menus now execute their installed healthy COB programs during production and movement: armcv, armfav, armflash, armstump, armsam, armmlv, armck, armpw, armrock, armham, armjeth and armwar. The twelve Core Vehicle Plant and Kbot Lab products do as well: corcv, corfav, corgator, corraid, cormist, corlevlr, cormlv, corck, corak, corstorm, corthud and corcrash. Core script playback is not Core combat parity; corraid remains the only Core unit with world weapon support. Kbot leg poses now advance through the original walk/MotionControl routines and settle after StopMoving. Create also initializes original visibility and static state for vehicles and Kbots.

`native_mobile_reference.py` runs the pinned original x86 interpreter for 300 ticks per unit. The scenario supplies health 100 and build remaining-percent 100 then 0. Where callbacks exist, it invokes Create, StartMoving/StopMoving twice, AimPrimary with supplied angles, and builder Activate/StartBuilding/StopBuilding/Deactivate. `compare_native_units.gd` matches all 7,320 snapshots (3,661 Arm, 3,659 Core), including piece transforms, motion targets/speeds, spin state, visibility, script statics, active thread PC/state, written properties and rendering flags. The compact result is native-mobile-validation.json. This does not compare firing, damage, destruction, renderer output or native world callback timing.

`test_produced_scripts.gd` exercises the actual production host for every menu entry, verifies completion/controller/script creation, changing walking poses, pad exit, stopping, movement callbacks and absence of VM faults: 144 checks across all four ground factories. This exposed the yard overlay's inconsistent treatment of odd-sized footprints. The terrain navigation samples an integer-anchored 3×3 area, but the building overlay previously used a geometric half-width anchor; larger vehicles were blocked at their initial pad cell. The overlay now uses the same integer anchor as terrain navigation. All twelve products exit the test yards. This is consistency within provisional navigation, not proof of native occupancy fidelity.

The real-map Kbot demo builds a Lab, queues two Peewees, waits for their exit and moves a selected Peewee. A rendered capture was inspected. Run Godot with `--path godot -- --kbot-demo --capture ABSOLUTE_PNG_PATH`; the normal verifier also runs this scenario headlessly. Factory placement in the demo derives its offset from the selected factory footprint to remain within Commander build range.

Production/movement uses healthy status as before. Damaged smoke requires RAND/EMIT_SFX support, and destruction requires more engine callbacks. Mobile builders now expose player construction orders; see MOBILE_BUILDERS.md. Combat, dynamic unit avoidance, terrain and yard fidelity, and exact renderer transformations remain unfinished. These are prerequisites toward the complete-game objective, not a completed game.
